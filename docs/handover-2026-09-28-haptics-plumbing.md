## For Claude's taste pass

Import named intents from `src/lib/haptics.js`:

```js
import { tapLight, tapMedium, success, warning, error } from "./lib/haptics.js";
```

- `tapLight()` → light impact, minor confirmation.
- `tapMedium()` → medium impact, an action landed.
- `success()` → success notification, target hit/month closed.
- `warning()` → warning notification, attention required.
- `error()` → error notification, action failed.

The helper returns a safely resolving promise. Call with `void tapMedium()`
for feedback that does not block the action. All plugin calls share a try/catch
that catches both synchronous throws and asynchronous rejections. Non-native
web/sandbox platforms and native wrappers without Haptics return immediately.
There is no web vibration fallback.

Exactly one example was added: `App.jsx`, `handleSave`, after the API
confirms `saved?.ok && saved.data`. It fires once per successful single-Bloc
submission. It does not fire for optimistic updates or failed saves.
No other haptic placements were selected. The separate `handleMultiLog` path
has none; Claude can decide its placement with Aadhil.
